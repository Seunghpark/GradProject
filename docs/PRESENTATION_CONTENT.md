## 2장 — 문제와 목표

- 경기 후 통계와 초기 상태의 예측 입력을 구분하여 설명할 필요
- 실제 경기 기록, 골드 흐름과 검토할 관찰 내용을 한 화면에서 제공
- 딥러닝을 실제 학습·서빙하고 단순 기준선과 같은 조건으로 비교
- 구현 성공과 새로운 경기에서의 일반화 성능을 별도로 평가

발표 노트: 목표는 과거 경기 분석 시스템과 재현 가능한 실험이다. 사용자 설문이나 승률 향상 실험은 수행하지 않았다.

## 3장 — 시스템과 자료 흐름

- React·TypeScript: Riot ID/지역 입력, 경기 선택, 통계·차트·확률·출처 표시
- FastAPI: ACCOUNT-V1 조회 → MATCH-V5 경기 상세·타임라인 수집
- SQLite 캐시 및 요청 간격·rate-limit 대응
- JSON 모형 순전파 → 경기 후 검토 → JSON 내보내기
- 키는 백엔드에만 저장, 실제·캐시·합성 자료 구분

시각자료 자리: 실제 구현을 단순화한 자료 흐름도. 키 값이나 PUUID 원문은 넣지 않는다.

발표 노트: 합성 데모를 실제 플레이어의 결과처럼 표시하지 않으며 모형과 경기의 출처가 다르면 확률 출력을 막는다.

## 4장 — 실제 데이터와 초기 정보 기준

- 고유 실제 경기 104개: KR 랭크 솔로/듀오, 패치 16.20/16.21
- 경기 시작 기간: 2026-10-20~2026-10-28
- 한 플레이어와 관련 참가자 다섯 명을 시드로 한 연결 편의 표본
- 골드·XP·CS·킬·포탑·드래곤의 파란 팀−빨간 팀 차이 6개 입력
- 완전한 프레임 중 540~600초 범위의 마지막 프레임 사용

발표 노트: 실제 선택된 프레임은 540.088-540.308초이다. 다음 프레임이 600초를 조금 넘기므로 정확히 10분 관찰이라고 말하지 않는다. 이후 이벤트와 최종 통계는 입력에서 제외한다.

## 5장 — 딥러닝 구조와 학습

- 구조: 6 → 16 → 8 → 4 → 1
- 세 은닉층 ReLU, 출력 시그모이드
- 가중치·편향: 112 + 136 + 36 + 5 = 총 289개
- MLPClassifier, L-BFGS, alpha=1.0, seed=42
- max_iter=2000, max_fun=20000, tol=1e-6, early_stopping=False
- 고정 설정으로 학습, 수렴 경고 없이 최적화 반복 1,062회

시각자료 자리: 입력 6개, 은닉층 16/8/4, 출력 1개를 표시한 실제 구조도.

발표 노트: L-BFGS 반복 횟수는 epoch 수가 아니다. 로지스틱 회귀를 단순히 딥러닝이라고 부른 것이 아니라 실제 다층 신경망을 학습한다. 신경망이 복잡하다는 사실은 더 좋은 예측을 보장하지 않는다.

## 6장 — 비교 실험과 정보 누출 방지

- 시간순 앞선 83경기 학습 / 이후 21경기 평가
- 분할 간 경기 ID 중복 없음, 모든 학습 경기 종료 후 평가 경기 시작
- StandardScaler는 학습 자료에만 적합
- 신경망과 로지스틱 회귀의 특성·표준화·분할·정답 일치
- 상수 기준선은 학습 파란 팀 승률 48/83 사용
- 지표: 정확도, ROC-AUC, Brier 점수(낮을수록 좋음)

발표 노트: 21개 평가 경기는 앞선 로지스틱 실험에서 이미 확인했다. 따라서 이번 결과는 이전에 본 분할을 재사용하는 탐색적 비교이며 새 독립 테스트가 아니다. 평가 성능에 맞춘 구조·seed·정규화 탐색은 하지 않았다.

## 7장 — 동일한 21경기에서의 결과

- 딥 MLP: 10/21 정답, 정확도 47.62%, AUC 0.49091, Brier 0.372683
- 로지스틱 회귀: 12/21 정답, 정확도 57.14%, AUC 0.60909, Brier 0.263561
- 상수 기준선: 10/21 정답, 정확도 47.62%, AUC 0.50000, Brier 0.259862
- 신경망은 기준선을 능가하지 못함
- 신경망의 확률 오차는 두 기준선보다 큼

시각자료 자리: 동일 평가셋의 지표를 정확히 옮긴 세 모형 비교 그림. Brier는 낮을수록 좋다는 설명을 포함한다.

발표 노트: 긍정적인 성능 주장으로 바꾸지 않는다. 정확도 차이는 소수 경기의 차이이며 대표성·통계적 우수성이나 확률 보정을 입증하지 않는다.

## 8장 — 과적합과 한계 분석

- 학습 진단: 79/83 정답, 정확도 95.18%, AUC 0.995833, Brier 0.034691
- 평가 정확도 47.62%와 큰 차이: 과적합 가능성과 일치
- 289개 파라미터에 비해 학습 자료가 83경기로 작음
- 연결된 플레이어 표본, 플레이어 중복, 한 지역·두 패치에 제한
- 평가셋 재사용으로 독립 검증 주장 불가

발표 노트: 95.18%는 이미 학습한 자료에서 계산한 진단값이며 검증 정확도가 아니다. 더 많은 층을 추가하는 것보다 다양한 자료와 학습 내부 검증, 보지 않은 평가셋 확보가 우선이다.

## 9장 — 구현 화면과 검증

- 실제 Riot ID 조회 및 경기 선택·필터
- 경기 통계와 전체 경기 골드 차이 흐름
- 초기 스냅샷 추정과 경기 후 관찰의 분리
- 출처가 명시된 합성 데모와 JSON 내보내기
- 저장 JSON 순전파와 측정 지표의 독립 재계산 일치
- 전체 테스트·브라우저 통합 결과는 최종 QA 기록에서 확인 후 기재

화면 자리: 새 신경망을 활성화하고 실제 통합 확인을 마친 실행 화면만 사용한다. docs/QA_RESULTS.md에 연결된 최신 증거를 확인한다. 샘플 제출 화면과 로지스틱 전용 화면은 새 신경망 검증 증거가 아니다.

발표 노트: 이전 39개 테스트 통과를 확장된 신경망 버전 전체의 통과로 옮겨 쓰지 않는다. 기능 테스트와 예측 성능 평가는 서로 다른 증거임을 설명한다.
