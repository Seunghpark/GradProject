## 요약

본 프로젝트는 리그 오브 레전드의 완료된 랭크 경기를 대상으로 플레이어별 경기 기록, 경기 후 통계, 팀 골드 차이 시각화 및 초기 경기 상태에 기반한 승패 추정 기능을 구현한 LolAi.gg이다. React와 TypeScript로 사용자 인터페이스를 구성하고 FastAPI 백엔드에서 Riot API를 호출하며, 인증키는 서버 설정에만 보관한다. 딥러닝 모형은 여섯 개 팀 차이 특성을 입력받는 6-16-8-4-1 구조의 다층 퍼셉트론으로, 세 개의 ReLU 은닉층과 하나의 시그모이드 출력층을 갖는다.

실제 KR 랭크 솔로/듀오 경기 104개를 시간순으로 분할하여 앞선 83개 경기로 학습하고 이후 21개 경기로 탐색적 비교를 수행하였다. 신경망은 학습 데이터에서 95.18% 정확도를 보였으나 평가 데이터에서는 47.62%, ROC-AUC 0.49091, Brier 점수 0.372683을 기록하였다. 동일 분할의 로지스틱 회귀는 57.14% 정확도와 Brier 0.263561, 상수 기준선은 47.62% 정확도와 Brier 0.259862를 보였다. 따라서 본 결과는 딥러닝 학습·추론 경로를 구현한 소규모 실험이며, 신경망의 예측 우수성을 입증한 결과가 아니다. 큰 학습·평가 성능 차이, 제한된 수집 표본 및 이전에 확인한 평가셋의 재사용을 주요 한계로 제시한다.

## 서론

경기 종료 후의 요약 통계는 플레이어의 기록을 정리하는 데 유용하지만, 경기 초반 어느 팀이 어떤 상태에 있었는지와 최종 결과를 구분하여 보여 줄 필요가 있다. 본 프로젝트의 목표는 완료된 경기의 기록을 조회하고, 명확히 정한 초기 정보만으로 결과를 추정하며, 경기 후 관찰 내용을 사용자가 검토할 수 있도록 제공하는 것이다.

구현 목표는 다음과 같다.

- Riot ID와 지역을 입력하여 실제 완료된 랭크 경기 기록을 조회한다.
- 경기 통계, 팀 골드 차이 흐름과 투명한 규칙 기반 경기 후 검토 문구를 제공한다.
- 세 은닉층을 갖는 실제 신경망을 학습하고 로지스틱 회귀 및 상수 기준선과 동일한 조건에서 비교한다.
- 학습 자료와 평가 자료, 실제 자료와 합성 데모 자료를 구분하고 재현 가능한 평가 기록을 남긴다.
- 네트워크 이용이 어려운 상황에서는 가상의 플레이어와 경기를 명시한 데모를 제공한다.

분석 범위는 완료된 경기의 회고적 분석이다. 실시간 코칭, 게임 중 의사결정 지시, 개인의 장기 실력 추정 또는 승률 향상에 대한 인과 검증은 수행하지 않았다. 기존 샘플 문서의 1,000경기, 6.7% 향상, 설문 결과를 본 프로젝트의 측정 결과로 사용하지 않는다.

서론에서 소개한 구현의 탐색적 결과는 신경망 47.62%, 로지스틱 회귀 57.14%의 평가 정확도이며, 신경망의 우수성을 확인하지 못하였다. 이하 관련연구에서는 선행 방법의 정보 시점과 범위를 정리하고, 제안 작품 소개에서는 자료·구조·신경망을 설명한다. 구현 및 결과분석에서는 동일 분할 비교와 한계를 제시하고, 결론 및 소감에서 결과와 개인의 경험을 구분한다.

## 제안 작품 소개

사용자는 React·TypeScript 화면에서 Riot ID, 지역과 자료 모드를 선택한다. FastAPI는 ACCOUNT-V1으로 Riot ID를 PUUID에 대응시키고, MATCH-V5를 통해 랭크 경기 ID, 상세 기록과 타임라인을 가져온다. 백엔드는 SQLite 캐시, 지역 경로 허용목록, 요청 간 간격 및 rate-limit 응답 처리를 적용한다.

화면은 플레이어별 요약 통계, 경기 선택과 결과 필터, 선택 경기의 KDA·CS/min·킬 관여율·시야 점수·챔피언 피해량, 팀 골드 차이 타임라인, 초기 상태의 승리 확률 추정 및 경기 후 검토 문구를 제공한다. 분석 결과는 JSON으로 내보낼 수 있다. 경기 후 검토는 관찰 가능한 통계에 기반한 규칙이며, 특정 통계가 패배를 유발했다는 인과 설명으로 제시하지 않는다.

실제, 캐시 및 합성 자료의 출처를 화면과 결과에 구분하여 표시한다. 합성 데모는 DemoPlayer라는 가상 플레이어를 사용하며 실제 플레이어의 조회 결과로 가장하지 않는다. 실제 자료로 학습한 모형은 합성 경기의 확률을 출력하지 않고, 합성 모형은 실제 경기에 적용하지 않는다.

Riot 키는 백엔드의 로컬 환경 설정에만 저장하며 프런트엔드 코드나 배포용 번들에 포함하지 않는다. 원시 경기 자료, 캐시 및 생성된 모형은 일반 소스 패키지에서 제외한다. 모형은 실행 가능한 직렬화 파일 대신 JSON 가중치와 정규화 정보를 사용한다. 서빙 경로에서는 입력과 모형의 차원·활성화·유한 수치 및 자료 출처를 확인한 후 표준 라이브러리로 순전파를 수행한다. 분석 캐시는 모형 파일 내용의 해시로 구분하여 다른 버전의 확률이 재사용되지 않도록 한다.

### 데이터와 전처리

분석용 스냅샷은 인증된 Riot API 응답에서 얻은 고유 경기 104개이다. 자료는 KR 서버의 소환사의 협곡 랭크 솔로/듀오 경기이며, 게임 시작 시각 범위는 2026년 10월 20일부터 10월 28일까지이고 패치는 16.20 및 16.21이다. 수집 시드는 한 플레이어와 해당 플레이어의 경기에서 확인한 참가자 다섯 명으로 구성되었다. 따라서 플레이어 중복 및 연결된 편의 표본에 따른 선택 편향이 있다.

경기 ID로 중복을 제거하고 경기 상세와 타임라인 ID의 일치, 지원 맵·큐, 경기 길이, 팀·참가자 구성과 완전한 초기 프레임을 검증한다. 하나의 경기에 파란 팀 관점의 표본 하나만 생성하여 같은 경기를 양 팀 관점으로 학습·평가에 중복시키지 않는다.

입력 특성은 파란 팀 합계에서 빨간 팀 합계를 뺀 다음 여섯 값이다.

- 골드 차이
- 경험치 차이
- 미니언 및 정글 몬스터 CS 차이
- 챔피언 처치 수 차이
- 파괴한 포탑 수 차이
- 처치한 드래곤 수 차이

초기 정보의 기준은 경기 시작 후 540,000ms 이상 600,000ms 이하 범위의 가장 늦은 완전한 프레임이다. 해당 프레임 시각 이후의 이벤트는 제외한다. 이번 실제 스냅샷에서 선택된 프레임은 540.088-540.308초, 즉 약 9분 시점이다. 다음 프레임이 엄격한 600초 기준을 조금 넘기기 때문에 이 값을 정확히 10분 시점의 관찰이라고 표현하지 않는다.

최종 KDA, 최종 피해량, 경기 종료 후 통계 및 최종 승패는 입력 특성에 포함하지 않는다. 최종 승패는 지도학습 및 평가의 정답으로만 사용한다. 화면의 전체 경기 골드 그래프와 경기 후 검토는 이후 정보를 포함하는 회고적 결과이며 초기 예측 입력과 구분한다.

### 딥러닝 모형

신경망 구조는 입력 6개, 은닉층 16개·8개·4개 뉴런, 출력 1개이다. 은닉층에는 ReLU, 출력에는 파란 팀 승리 확률을 위한 시그모이드를 사용한다. 표준화한 입력이 각 완전연결층과 비선형 활성화를 순차적으로 통과하며, 빨간 팀 플레이어의 화면에는 파란 팀 확률의 보수를 표시한다.

학습 가능한 가중치와 편향의 수는 다음과 같다.

- 입력 6개에서 첫 은닉층 16개: 6×16 + 16 = 112개
- 은닉층 16개에서 8개: 16×8 + 8 = 136개
- 은닉층 8개에서 4개: 8×4 + 4 = 36개
- 은닉층 4개에서 출력 1개: 4×1 + 1 = 5개
- 총합: 112 + 136 + 36 + 5 = 289개

학습에는 scikit-learn의 MLPClassifier를 사용한다. 세 은닉층을 포함하는 실제 신경망을 학습하므로 단순히 로지스틱 회귀의 명칭을 딥러닝으로 바꾼 구현이 아니다. 다만 이 구체적인 구조가 학과·지도교수의 평가 범위를 충족하는지는 실제 구현과 함께 확인해야 하며, 승인 사실을 가정하지 않는다.

최적화는 정규화된 log loss에 대한 L-BFGS를 사용한다. 고정 설정은 alpha=1.0, random_state=42, max_iter=2000, max_fun=20000, tol=1e-6, early_stopping=False이다. 이번 실행은 수렴 경고 없이 최적화 반복 1,062회 후 종료되었다. 이를 epoch 수로 해석하지 않는다. 구조와 설정은 이 비교 실행 전에 정했으며 평가 성능을 높이기 위한 구조·seed·정규화 계수 탐색을 수행하지 않았다.

정규화에는 StandardScaler를 사용하고 평균과 표준편차는 학습 분할에서만 계산한다. 저장된 JSON은 정규화 정보, 층별 가중치·편향, 구조, 자료 출처, 수렴 정보 및 평가 기록을 포함한다. 서비스는 이를 읽어 순전파를 수행하며 학습 시의 표준화와 팀 방향을 그대로 유지한다.

## 구현 및 결과분석

### 실험 방법

전체 104개 경기를 경기 시작 시각 순으로 정렬하여 앞선 83개를 학습에, 이후 21개를 평가에 사용한다. 같은 경계 시각의 경기는 서로 다른 분할로 나누지 않는다. 분할 간 경기 ID가 겹치지 않으며, 모든 학습 경기는 첫 평가 경기의 시작 전에 종료되었음을 확인하였다.

학습 분할은 파란 팀 승리 48개·빨간 팀 승리 35개, 평가 분할은 파란 팀 승리 10개·빨간 팀 승리 11개이다. 신경망과 로지스틱 회귀는 동일 특성, 학습 전용 표준화, 학습·평가 경기 및 정답을 사용한다.

비교 대상은 다음과 같다.

- 딥 MLP: 6-16-8-4-1 다층 신경망
- 로지스틱 회귀: C=1.0, max_iter=2000, random_state=42
- 상수 기준선: 학습 분할의 파란 팀 승리 비율인 48/83을 모든 평가 경기의 확률로 사용

정확도는 0.5를 분류 기준으로 계산하며, ROC-AUC와 Brier 점수를 함께 보고한다. Brier 점수는 확률과 실제 결과 사이의 제곱 오차이므로 낮을수록 좋다. 학습 자료에 대한 지표는 적합 상태를 확인하는 진단값으로만 구분하여 기록한다.

중요하게도 21개 평가 경기는 앞선 로지스틱 회귀 실험에서 이미 확인한 자료이다. 이번 신경망 실험은 해당 분할을 재사용하는 탐색적 비교이며, 새롭고 독립적인 최종 테스트로 주장하지 않는다. 평가 지표가 더 좋은 모형을 골라 이겼다고 주장하거나, 평가셋을 반복 확인하면서 설정을 조정하지 않았다.

### 측정 결과와 해석

동일한 21개 평가 경기에서 관찰한 결과는 다음과 같다.

- 딥 MLP: 10/21개 정답, 정확도 47.62%, ROC-AUC 0.49091, Brier 점수 0.372683
- 로지스틱 회귀: 12/21개 정답, 정확도 57.14%, ROC-AUC 0.60909, Brier 점수 0.263561
- 상수 기준선: 10/21개 정답, 정확도 47.62%, ROC-AUC 0.50000, Brier 점수 0.259862

신경망의 학습 진단은 79/83개 정답, 정확도 95.18%, ROC-AUC 0.995833, Brier 점수 0.034691이다. 이 값은 이미 학습한 자료에서 계산했으므로 검증 정확도로 사용하지 않는다. 학습 정확도와 평가 정확도의 약 47.56%p 차이는 이 작은 표본에서 과적합이 발생했을 가능성과 일치한다.

평가 정확도에서 신경망은 상수 기준선과 같고 로지스틱 회귀보다 두 경기를 더 틀렸다. 신경망의 Brier 점수는 두 기준선보다 나쁘므로 확률 품질도 개선되었다고 볼 수 없다. 로지스틱 회귀 역시 Brier 점수에서는 상수 기준선보다 좋지 않았다. 따라서 모형의 복잡도가 높다는 이유만으로 예측 우수성이나 신뢰할 수 있는 확률을 주장할 수 없다.

별도의 표준 라이브러리 순전파로 저장된 가중치의 평가 결과를 다시 계산했으며, 기록된 지표와의 차이가 1e-12 이내임을 확인하였다. 이 검증은 구현한 추론 경로의 일치성을 뒷받침하지만 독립 데이터에 대한 일반화 검증은 아니다.

시스템·신경망 구조와 실측 결과 도식은 직접 작성한다. 저장된 HWP 안내에 따라 화면 갈무리는 최소화하고, 그림은 본문과 같은 글꼴 및 본문 반 쪽 이하 크기로 구성한다. 그림 아래 번호·설명, 표 위 번호·설명을 붙인다. 실행 증거가 필요한 경우에만 새 신경망 통합 화면을 최소한으로 사용한다. 이전 샘플 업로드 화면이나 로지스틱 회귀 전용 화면을 새 신경망의 실행 증거로 사용하지 않는다. 테스트 건수·전체 실행 결과·브라우저 재시작 검증은 최종 작성 시 docs/QA_RESULTS.md와 docs/TEST_RESULTS.txt의 최신 기록을 확인하여 옮긴다. 앞선 39개 테스트 통과 기록을 확장된 신경망 버전 전체의 통과 기록으로 재사용하지 않는다.

### 한계와 후속 과제

표본은 104경기로 작고 평가 자료는 21경기에 불과하다. 특정 플레이어들과 연결된 KR 자료, 두 개의 가까운 패치 및 플레이어 중복으로 인해 다른 서버·티어·패치·플레이어 집단에 일반화하기 어렵다. 계층형 표본 수집이나 플레이어 단위의 외부 분리 검증도 수행하지 않았다.

289개 학습 파라미터에 비해 학습 경기는 83개뿐이며 실제로 큰 학습·평가 차이를 관찰하였다. 더 많은 은닉층이나 더 큰 모델을 추가하는 것만으로 해결된다고 가정하지 않는다. 충분히 다양한 데이터를 수집하고, 학습 내부의 검증만으로 설정을 정한 뒤, 전혀 보지 않은 새 평가셋에서 다시 비교하는 절차가 필요하다. 확률 보정, 반복 시계열 검증 및 패치 변화에 대한 평가는 수행하지 않았다.

기능 검증도 연구 성능 평가와 분리해야 한다. API·모형 테스트 통과는 잘못된 자료나 추론 경로를 점검하는 증거이며 실제 경기의 예측 우수성 또는 서비스 운영 안정성을 보장하지 않는다. 사용자 연구와 플레이어 개선 효과 측정은 수행하지 않았다.
